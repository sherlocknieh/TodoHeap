# 任务图布局逻辑

任务图的节点位置由 `frontend/src/components/MindMapWrapper.vue` 的 `graphLayout` 一次性算出：先把任务树整理成可见的有向图，再沿主方向分层、沿交叉方向逐层排布。本文记录这套规则的现状、约束与验证方式。

---

## 一、数据入口

`graphLayout` 只吃 `props.nodes`（`TodoGraph.vue` 由 store 的 `treeNodes` 映射而来）与跨视图共享的折叠状态 `collapsedSet`。

| 步骤 | 位置 | 作用 |
| --- | --- | --- |
| 可见图 | `buildGraphData` | 先完整遍历森林收集节点与边；再按折叠状态从根扩散求可见集；`isRef` 引用节点不占节点位，只折成一条指向 `targetId` 的边；折叠节点的出边整条剔除 |
| 量节点 | `measureNode` | 按 canvas 实测像素折行；高度 = `paddingTop + 行数 × lineHeight + 12`（有副标题再加 14）；编辑中的节点不截断行数 |
| 分层 | Tarjan + 缩点最长路径 | 强连通分量缩点后按最长路径分层，环内节点按 id 顺序各占一层，保证环仍沿主方向可读 |
| 坐标 | `layerStart` / `crossCenter` | 主方向每层固定为节点宽度，层间留 `mainGap`；交叉方向由下文规则求出 |

常量集中在文件前部：节点宽 `216`、`crossGap` 24、`mainGap` 84、字号 13、行高 16。

---

## 二、主方向（层级）

1. 可见边求出强连通分量（Tarjan），分量缩点后做最长路径分层，得到每个节点的 `nodeLayer`。
2. 每层厚度固定为节点宽度 `nodeWidth`，逐层累加 `mainGap`，得到 `layerStart`。
3. 只有两种横向布局：`right` 是正向，`left` 把主坐标翻到内容另一端；交叉方向恒为 `y`。
4. 坐标原点钉在根节点左上角，展开/折叠只改其它节点的相对位置，根节点在画布上不动。

---

## 三、交叉方向（同层排开）

### 层内顺序

沿可见边从 `props.nodes` 的根做深度优先遍历，记录 `dfsIndex`；每层按 `dfsIndex` 排序作为固定顺序。层内顺序不做重排，否则折叠/展开后同一批节点会互相换位、整图漂移。

### 子树块跨度

每个节点在交叉方向要占一整块空间，用来把同层邻居推开，让展开出来的子节点带不被邻支挤住：

```
laneChildren: 只认「紧邻下一列」的子节点（childLayer === parentLayer + 1）
laneOwner:    一个子节点只归第一个紧邻父级，避免多父各占一份
blockSizeOf:  block = max(节点自身交叉尺寸, Σ 子节点 block + 间隔)
```

递归只沿「层 + 1」走，不会成环，结果按 id 记忆化。

### 层内落位（PAVA）

初始坐标按层内顺序用块跨度依次排开。随后每层做保序回归（PAVA）：

- 相邻节点的期望中心差 = `(前块 + 后块) / 2 + crossGap`，投影到「顺序不变、间距不小于该值」的约束上。
- 投影后整层按期望均值平移回来，抵消逐层累积的漂移。
- 因为间距按块而不是节点自身高度，展开一个节点时，它的兄弟会被推到子树块外侧；折叠后块收缩，兄弟收回。

### 上下居中

每层落位后做 `relaxLayer`：

- `down`：节点拉向其全部前向父级的位置（多父取平均）。
- `up`：父节点居中于子节点带。
- 交替 3 轮，先深后浅再浅后深，每轮都重新投影回间距约束。

多父节点按所有前向父级的平均位置定位，跨层父链同样参与，保证多父关系在位置上可见。

### 兄弟分支的异常空白

3 轮居中结束后，`limitGaps` 从浅到深扫描每层相邻节点：

- 只处理同一父级下的兄弟（`shareParent`），不同父级的相邻节点不比较；
- 用 `blockBoundsOf` 求两块的实际可见范围（节点加 `laneChildren` 后代），比较边缘空白；
- 空白超过 `2 × crossGap` 时，把上方节点连同它的 `laneChildren` 子树一起下移，使边缘间距回到 `2 × crossGap`。

这样展开后由多父链造成的异常大空白会被吸收，而块跨度预留的正常展开空间不变。

## 四、连线与包围盒

- 出边从折叠/加号按钮中心出发，入边落在子节点边框上并后退一个箭头长度，箭头尖端正好贴边。
- 折叠/加号按钮挂在节点外侧的画布上（`controlPointFor`），配色统一按画布底走，不跟随节点底色；根节点同样如此，否则半透明白底压在浅色画布上几乎不可见。
- 正向边用三次贝塞尔，两端控制点沿主方向，保证在节点处水平进出。
- 回边（目标层不晚于来源层）绕到内容外侧，按边序号错开通道，用圆角折线返回。
- 内容包围盒由节点实际尺寸求出，供「适应视图」与聚焦使用；回边通道不计入包围盒。

---

## 五、约束与取舍

| 约束 | 现状做法 | 代价 |
| --- | --- | --- |
| 展开时子节点带不被邻支挤住 | 同层间距按子树块跨度计算，收敛后由 `limitGaps` 吸收兄弟分支间的异常空白 | 深而宽的分支会占较高的块；折叠该分支即可收缩 |
| 父子连线保持短而水平 | 父节点居中于子节点带，父子层位置互相吸引 | 深分支的块会被完整预留，这是整块让位的正常结果 |
| 多父任务只出现一次 | 节点归一次，另一条父链画成跨层边；定位时取所有前向父级的平均 | 跨层边较长，节点会落在多条父链之间 |
| 展开后不留异常大空白 | `limitGaps` 只对同父级兄弟按实际可见边缘比较，超过 `2 × crossGap` 时整支子树下移 | 整支子树会跟着平移，父节点随后由 `up` 重新居中 |
| 折叠/展开不抖动 | 层内顺序固定为 DFS 序，根节点钉在原点 | 新增节点不会自动挤进「视觉上最近」的位置 |

---

## 六、验证

- `cd frontend && npm run build` 必须通过，`npm test` 覆盖 store 层。
- 手动检查：展开多级子任务的分支，兄弟让位、父子连线水平；多父链接展开后节点落在父链之间，同父级兄弟边缘空白不超过 `2 × crossGap`，无节点重叠。
