# 日历导入导出与订阅

TodoHeap 的日历功能围绕 `schedules`（日程事件）工作：可以把外部日历导入、把日程导出为 `.ics`，也可以生成只读订阅链接，让系统日历自动跟随更新。

::: tip 范围说明
导出与订阅只包含**日程事件**。任务的截止时间不属于日程事件，既不会出现在日程视图，也不会被写进 `.ics`。
:::

## 从日历软件导入

1. 在日历软件中导出 `.ics` 文件（Google 日历、Apple 日历、Outlook 都支持）
2. 打开日程页，点击右上角「导入」，选择文件
3. 确认事件数量无误后点击「开始导入」

也可以在「设置 → 日历 → 导入日程」中完成同样的操作。

导入规则：

| 情况 | 行为 |
| --- | --- |
| 普通事件 | 按开始与结束时间写入日程 |
| 缺少结束时间 | 定时事件补足 1 小时，全日事件补足 1 天 |
| 重复事件（RRULE） | 展开为未来一年内的实例，最多 200 条 |
| 缺少开始时间 | 跳过，并在预览里提示数量 |
| 同一文件重复导入 | 带 UID 的事件按「UID + 实例开始时间」去重，不会生成重复日程 |

导入时会把 ICS 的结构化字段分别落到对应列：

| ICS 字段 | schedules 列 |
| --- | --- |
| `SUMMARY` | `title` |
| `DESCRIPTION` | `notes` |
| `LOCATION` | `location` |
| `URL` | `url` |
| `ATTENDEE` | `attendees`（优先取 `CN` 显示名） |
| `DTSTART` 为 DATE 型 | `all_day` |
| `STATUS` | `status`（confirmed / tentative / cancelled） |
| `COLOR` | `color` |
| `VALARM` 的 `TRIGGER` | `reminder_minutes` |
| `UID` | `external_id` |

导入的日程会在日程页按日期展示，地点与参与人直接显示在标题下方；单击事件可在右侧详情面板里修改标题、时间、地点、链接、参与人、状态、颜色、提醒与备注，也可以直接删除。

## 导出为 ICS

在日程页点击「导出」，或在「设置 → 日历 → 导出日程」中操作。导出的文件包含全部日程事件及地点、链接、参与人、状态、颜色与提醒，时间为 UTC（全天事件按日期），可直接导入系统日历或其他日历软件。

## 订阅日历

订阅后，日程变化会自动同步到日历软件，不需要反复导出。

1. 打开「设置 → 日历 → 日历订阅」
2. 点击「生成订阅链接」
3. 复制链接，在系统日历中选择「添加日历订阅 / 通过 URL 添加日历」
4. 日历软件会按自身策略定期拉取，TodoHeap 建议的刷新间隔为 30 分钟

订阅链接形如：

```text
https://<项目>.supabase.co/functions/v1/calendar_feed?token=<32 位随机令牌>
```

### 安全与失效

- 链接本身就是只读凭据，拿到链接的人可以看到你的日程标题、备注、地点与参与人，**请勿公开分享**
- 点击「重新生成」会立刻让旧链接失效，再在日历软件里更新链接
- 点击「停用」会删除令牌，旧链接返回 404

## 当前限制

- 订阅是单向只读：在日历软件里修改不会写回 TodoHeap
- 不包含任务截止时间，也不包含重复规则，展开后的实例是独立事件
