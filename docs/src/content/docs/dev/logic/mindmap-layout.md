# 任务图布局逻辑

任务图的节点位置由 `frontend/src/utils/mindmapLayout.js` 算出：主方向先按可见边分层，交叉方向再按布局模式定位。本文记录两种模式的现状、约束与验证方式。

---

## 一、布局模式

右下角视图控件里的第三个按钮在两种模式间轮换，选择存本地（`layoutModeOptions`、`cycleLayoutMode`、`persistedRef('mindmap-layout-mode')`）：

| 模式 | 入口 | 做法 |
| --- | --- | --- |
| 紧凑布局（默认，`compact`） | `computeGraphPositionsCompact` | 树排版 → 多父归中 → 空间回收，尽量压缩无谓空白 |
| 标准布局（`standard`） | `computeGraphPositionsStandard` | 经典思维导图：子树按真实占地递归排布，父节点严格居中，多父归中后压紧兄弟块 |
| 平衡布局（`balanced`） | `computeGraphPositionsBalanced` | 标准布局打底 + 3 轮有界父子吸引（单轮 ≤120px），高度下降、居中略松 |

两种模式共用同一套输入输出（节点、边、方向 → 坐标、分层、包围盒），渲染层与连线生成不感知模式。`computeGraphPositions` 按 `mode` 分发，未知值退回紧凑布局。

---

## 二、数据入口

`computeGraphLayout` 只吃传入的森林与跨视图共享的折叠状态 `collapsedSet`。正常渲染传入 `props.nodes`（`TodoGraph.vue` 由 store 的 `treeNodes` 映射而来）；拖拽排序时显示层改用 `dropPreviewForest` 临时插入占位槽，命中检测仍走不含占位槽的 `hitLayout`。

| 步骤 | 位置 | 作用 |
| --- | --- | --- |
| 可见图 | `buildGraphData` | 先完整遍历森林收集节点与边；再按折叠状态从根扩散求可见集；`isRef` 引用节点不占节点位，只折成一条指向 `targetId` 的边；折叠节点的出边整条剔除 |
| 量节点 | `measureNode` | 按 canvas 实测像素折行；高度 = `paddingTop + 行数 × lineHeight + 12`（有副标题再加 14）；编辑中的节点不截断行数 |
| 分层 | Tarjan + 缩点最长路径 | 强连通分量缩点后按最长路径分层，环内节点按 id 顺序各占一层。多父任务的额外父级是引用边，最长路径保证它落在所有父级之后，不会被挤成同层回边 |
| 坐标 | `computeGraphPositions` | 主方向每层固定为节点宽度、层间留 `mainGap`；交叉方向按模式求解 |

常量集中在模块前部：节点宽 `216`、`crossGap` 24、`mainGap` 84。

---

## 三、紧凑布局（默认）

交叉方向分三步，每一步只做一件事：

### 1. 树排版

- 树边只认非引用边（`isRef === false`）；引用边是多父任务的额外父级，不参与树的留位。
- 子树块跨度 `blockSizeOf` 沿树后代递归：`block = max(节点自身高度, Σ 子节点 block + crossGap)`。
- 层内顺序固定为可见边的深度优先序，兄弟沿用 `child_ids` 顺序；顺序不做重排，避免展开/折叠后同一批节点互相换位。
- 自深到浅 4 轮：父节点移到 `平均(树子节点中心)`，再用子树块跨度做 PAVA（保序回归）投影，保证同层不重叠。

### 2. 多父归中

- 多父节点 = 父级数量 ≥ 2（树父级 + 至少一条引用边），位置取**所有父级中心的平均**。
- 同层投影改用真实节点高度而不是子树块，并把多父节点的权重设为 200：普通邻居让位，平均位置优先成立。
- 归中只影响该节点自身，它的子树由下一步重新收敛。

### 3. 空间回收

- 交替收敛最多 24 轮：
  - 自深到浅：普通节点移到 `平均(树子节点中心)`；
  - 自浅到深：子节点移到 `平均(所有父级中心)`；
  - 每层用真实节点边缘 + `crossGap` 做加权 PAVA 投影，顺序不变、间距不小于 24。
- 每轮末尾重新落位多父节点；循环结束后再做一次多父落位，避免在收敛阈值附近被邻居挡住。
- 收敛判据：单轮最大位移 < 0.5px。整图从「按子树块预留」变成「按真实边缘贴紧」，兄弟分支之间不再留下异常空白，父子距离也随之缩短。

### 锚点与包围盒

- 坐标原点钉在根节点左上角，展开/折叠只改其它节点的相对位置，根节点在画布上不动。
- 内容包围盒由节点实际尺寸求出，供「适应视图」与聚焦使用；回边通道不计入包围盒。

### 层内顺序的边界

层内顺序固定为 DFS 序。多父节点的理想位置若越过同层相邻节点，会被夹在邻居边缘（保持 24 间距），不会为了归中交换顺序；这是为了折叠/展开时不整图漂移。

## 四、标准布局（经典思维导图）

- 树边只认非引用边。子树块按真实占地递归：子节点按 `DFS` 顺序堆叠、间距 `crossGap`，父节点落在子节点中心的平均值；父节点比子级带更高时整块向下扩，块高度就是这棵子树的真实占地。
- 根块依次向下堆叠；层内顺序固定为 DFS 序，不做重排。
- 多父节点（父级数量 ≥ 2）取**所有父级中心的平均**，整棵子树一起平移，块内相对位置不变；随后每层按真实节点边缘做加权 PAVA，只补足重叠，多父节点权重 200。
- 归中与分离交替 3 轮，结束后不再做整层压缩。
- 多父节点整块平移后会离开原来的兄弟块，留下大段空隙。布局以多父节点为锚，把它前后连续的普通兄弟块按 24 重新贴紧；由深到浅处理，外层使用内层压紧后的块边界。最后只按节点真实边缘补足重叠，不按块边界撑开不相干的分支。

特点与代价：

- 父节点严格居中：实测 43 个有子节点里 40 个完全居中；多父节点精确落在父级平均位置（实测 3 个偏差均为 0）。
- 多父节点留下的兄弟块空隙会被重新压紧到 24（实测顶部 `PPT` 与 `TodoHeap` 之间由 278 降到 24，最高节点随之下移 236px）。
- 没有整层向下压缩，空白只来自子树的真实占地，不会出现「明明有空间却绕远」的整块预留。
- 代价是整图仍偏高：99 个可见节点时标准布局高 3948、紧凑布局高 2200。
- 多父节点被平移到平均位置后，它原来的父级会失去居中（例如「文章项目」与「新增/完善两篇知乎文章」偏差 194）；这是多父链接与父子居中二选一的取舍。

## 五、平衡布局（有界父子吸引）

- 以标准布局的结果为底，再跑 3 轮：父节点向树子节点带平均靠拢、子节点向父级平均靠拢，每轮单方向位移不超过 120px；每步之后按真实节点边缘分离，并重新压紧多父锚点。
- 有界的目的：只把过长的父子连线压缩一部分，不推倒标准布局的块结构。
- 实测（99 节点）：高度 3948 → 3127（约 -21%），最高节点下移 513px；父节点偏离子级平均值的平均为 41px、p90 98px、最大 169px（标准布局 40/43 完全居中，最大 245）。
- 定位：介于标准与紧凑之间。要严格居中选标准，要最小高度选紧凑。

## 六、连线与包围盒

- 出边从折叠/加号按钮中心出发，入边落在子节点边框上并后退一个箭头长度，箭头尖端正好贴边。
- 折叠/加号按钮挂在节点外侧的画布上（`controlPointFor`），配色统一按画布底走，不跟随节点底色；根节点同样如此。
- 正向边用三次贝塞尔，两端控制点沿主方向，保证在节点处水平进出。
- 回边（目标层不晚于来源层）绕到内容外侧，按边序号错开通道，用圆角折线返回。
- 内容包围盒由节点实际尺寸求出，供「适应视图」与聚焦使用；回边通道不计入包围盒。

## 七、约束与取舍

| 约束 | 现状做法 | 代价 |
| --- | --- | --- |
| 展开时子节点带不被邻支挤住 | 紧凑布局先用树块留位，再用真实边缘回收空白 | 深而宽的分支仍会占较高空间，折叠该分支即可收缩 |
| 父子连线保持短而水平 | 父节点居中于树子节点带，子节点再贴近父级平均 | 多父节点与其额外父级之间仍可能跨层 |
| 多父任务只出现一次 | 最长路径把它放到所有父级之后；坐标取所有父级中心平均并且高权重 | 层内邻居先占位时，归中会被夹在邻居边缘 |
| 展开后不留异常空白 | 紧凑布局交替收敛、按真实边缘投影 | 层内顺序固定，不能靠交换顺序消除冲突 |
| 折叠/展开不抖动 | 层内顺序固定为 DFS 序，根节点钉在原点 | 新增节点不会自动挤进「视觉上最近」的位置 |

---

## 八、验证

- 自动：`cd frontend && npx vitest run src/utils/mindmapLayout.test.js`，覆盖多父归中、父节点居中、同层不重叠且结果稳定、三种模式分发、兄弟块压紧与左右方向翻转。
- 构建：`cd frontend && nub run build` 必须通过。
- 手动：切换两种布局模式；打开多父任务的分支，节点应落在父级平均位置附近、与同层邻居保持 24 间距；同层不重叠，兄弟分支之间没有大段空白。
