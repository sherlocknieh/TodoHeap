# 详情右栏的父链展示

任务详情右栏在标题输入框上方用一行小字显示完整父链；任务有多个父级时，行尾角标可展开全部链路。父链只读任务数据，不改变任何父子关系。

## 数据前提

`child_ids` 是唯一的父子来源，一个任务可以有多个父级、也可以成环（见[任务顺序](./task-order.md)）。因此「完整父链」不是一条线，而是**若干条根到当前任务的简单路径**，数量会随祖先分叉增长。展示层因此拆成三个口径：

| 口径 | 来源 | 用途 |
| --- | --- | --- |
| 祖先层（大致路径） | 扁平任务 + `child_ids` 反向索引，按距当前任务的跳数分层 | 标题上方那一行，DAG 去重 |
| 全部父链 | 同一份索引，深度优先枚举简单路径 | 多父角标的计数与精确路径列表 |
| 展示主链 | `treeNodes` 里 `buildTaskForest` 写回的首现 `parent_id` | 只把精确路径里当前视图那条排到最前 |

主链与「删除后焦点落点」「拖拽命中」用的是同一条展示父链（见[任务图删除后的焦点落点](./graph-delete-focus.md)），所以精确路径列表里的第一行和操作落点不会互相矛盾。

## 展示规则

- 根任务「全部任务」是系统节点，不算链首；所有顶层任务的父链为空，整行隐藏。
- 祖先层与标题输入框一样左对齐。按距当前任务的跳数分层，**最远的一层在前**：同层用 `/` 表示并列父级，层间用 `›`，例如 `项目 / 另一支 › 子项目 / 分支子`。宽度不足时裁掉尾部，悬停整行可在 `title` 里看完整路径。
- 同一祖先在多条路径上只出现一次；环因节点只记录一次而自然终止。
- 每个祖先可点，点击等同于选中该任务：只切换详情内容，不切换视图。
- 多父时行尾显示 `+N`（N = 精确路径数 − 1），点开内联列表，每条精确路径一行，当前视图那条排最前，其余按枚举顺序。
- 唯一祖先封顶 40、深度封顶 20，标题行末尾加 `…`；精确路径深度封顶 20、条数封顶 20，列表底部提示「仅显示前 20 条」。成环的分支标记 `↻` 并停止回溯。
- 回收站里的已删除任务不在 `treeNodes` 中，父链整行不显示。

## 实现

- `frontend/src/utils/taskChain.js`：
  - `displayChainOf(treeNodes, id)` 建立首现实体节点索引后沿 `parent_id` 回溯，跳过 `_isRef` 回边节点、根任务与环；
  - `ancestorLayersOf(items, id, { maxDepth, maxNodes })` 从当前任务向上 BFS，首次到达即最短跳数，按层返回 `{ layers, truncated }`，远层在前；
  - `allChainsOf(items, id, { maxDepth, maxPaths })` 用同一份父级索引深度优先枚举简单路径，返回 `{ chains, truncated }`，每条链带 `cycle` 标记；
  - 三者共用 `buildParentIndex`，父级顺序沿用任务数组顺序。
- `components/TodoDetailEditor.vue`「[父链/面包屑]」放在详情分区内容顶部；角标展开的是内联面板，靠 `useSectionStack` 的 `auto` 高度自动重新测量，不浮在内容之上，避免被分区体 `overflow-hidden` 裁掉。
- 扁平任务由 `[rootTodo, ...tasks]` 拼回：store 的 `tasks` 已排除根任务，枚举时再补回。

## 取舍

- 分层是**近似**路径：同层只表示并列可选，不保证层内节点与上一层一一配对；精确关系放在 `+N` 的路径列表里。
- 不做「全部链路逐行常驻」：右栏宽 320px，多父或祖先分叉时行数会指数增长，把标题和描述整体往下推。
- 不做「只显示直接父级」：丢掉完整链路，无法判断当前任务挂在哪条分支下。
- 不做「只显示一条主链」：多父任务的其它分支完全看不见，用户无法从详情跳过去。
- 路径枚举不缓存在 store：只在详情面板打开且祖先层非空时计算，封顶后成本有界。

## 验证

- `cd frontend && npx vitest run src/utils/taskChain.test.js`：覆盖单父回溯、顶层无链、回收站缺失、多父分层、菱形去重、环、深度/条数截断。
- 手动：选一个多父任务，标题上方按层显示去重后的祖先（同层 `/`、层间 `›`）；点 `+N` 展开全部精确路径，点任一祖先切到该任务详情；顶层任务不显示父链行；回收站任务不显示。
