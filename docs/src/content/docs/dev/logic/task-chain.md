# 详情右栏的父链展示

任务详情右栏在标题输入框上方用多行小字显示父链。任务有多个父级时按跳数去重成分层的大致路径，不枚举全部组合。父链只读任务数据，不改变任何父子关系。

## 数据前提

`child_ids` 是唯一的父子来源，一个任务可以有多个父级、但不允许成环（见[任务顺序](./task-order.md)与[环形依赖的写入拦截](./task-cycle-guard.md)）。因此「完整父链」不是一条线，而是**若干条根到当前任务的简单路径**，数量会随祖先分叉增长。展示层只保留**去重后的祖先层**：按距当前任务的跳数分层，同一祖先只出现一次。

这里和「删除后焦点落点」「拖拽命中」用的展示父链（`buildTaskForest` 写回的 `parent_id`）口径不同：那两处只需要当前视图看到的一条链，父链展示要让所有父级都能被点到，所以走 `child_ids` 反向索引。

## 展示规则

- 根任务「全部任务」是系统节点，不算链首；所有顶层任务的父链为空，整行隐藏。
- 与标题输入框一样左对齐，宽度不足时自动折行；每个祖先保持单行，不会在标题中间断开。
- 按距当前任务的跳数分层，**最远的一层在前**：同层用 `/` 表示并列父级，层间用 `›`，例如 `项目 / 另一支 › 子项目 / 分支子`。
- 同一祖先在多条路径上只出现一次；历史数据里残留的环因节点只记录一次而自然终止。
- 每个祖先可点，点击等同于选中该任务：只切换详情内容，不切换视图。
- 唯一祖先封顶 40、深度封顶 20，超出时行末加 `…`。
- 回收站里的已删除任务不在任务数组中，父链整行不显示。

## 实现

- `frontend/src/utils/taskChain.js`：
  - `buildParentIndex` 汇总 `child_ids` 反向关系，父级顺序沿用任务数组顺序；
  - `ancestorLayersOf(items, id, { maxDepth, maxNodes })` 从当前任务向上 BFS，首次到达即最短跳数，按层返回 `{ layers, truncated }`，远层在前。
- `components/TodoDetailEditor.vue`「[父链/面包屑]」放在详情分区内容顶部，`flex flex-wrap` 直接折行；`useSectionStack` 的 `auto` 高度随行数重新测量。
- 扁平任务由 `[rootTodo, ...tasks]` 拼回：store 的 `tasks` 已排除根任务，展示时再补回。

## 取舍

- 分层是**近似**路径：同层只表示并列可选，不保证层内节点与上一层一一配对。
- 不做全部路径的展开列表：路径数可指数增长，而去重后的祖先层已经覆盖全部可跳转的上级。
- 不做「只显示直接父级」：丢掉完整链路，无法判断当前任务挂在哪条分支下。
- 不做「只显示一条主链」：多父任务的其它分支完全看不见，用户无法从详情跳过去。
- 每次只读任务数组，不缓存；封顶后成本有界。

## 验证

- `cd frontend && npx vitest run src/utils/taskChain.test.js`：覆盖多父分层、菱形去重、历史环、深度截断、唯一祖先截断、顶层与未知任务。
- 手动：选一个多父任务，标题上方按层多行显示去重后的祖先（同层 `/`、层间 `›`）；点任一祖先切到该任务详情；顶层任务与回收站任务不显示。
