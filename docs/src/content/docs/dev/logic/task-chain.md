# 详情右栏的父链展示

任务详情右栏在标题输入框上方用一行小字显示完整父链；任务有多个父级时，行尾角标可展开全部链路。父链只读任务数据，不改变任何父子关系。

## 数据前提

`child_ids` 是唯一的父子来源，一个任务可以有多个父级、也可以成环（见[任务顺序](./task-order.md)）。因此「完整父链」不是一条线，而是**若干条根到当前任务的简单路径**，数量会随祖先分叉增长。展示层因此拆成两个口径：

| 口径 | 来源 | 用途 |
| --- | --- | --- |
| 展示主链 | `treeNodes` 里 `buildTaskForest` 写回的首现 `parent_id` | 标题上方那一行，与列表/导图当前看到的位置一致 |
| 全部父链 | 扁平任务 + `child_ids` 反向索引 | 多父角标的计数与展开列表 |

主链与「删除后焦点落点」「拖拽命中」用的是同一条展示父链（见[任务图删除后的焦点落点](./graph-delete-focus.md)），所以详情里看到的上级和操作落点不会互相矛盾。

## 展示规则

- 根任务「全部任务」是系统节点，不算链首；所有顶层任务的父链为空，整行隐藏。
- 主链从根排到最近父级，溢出时裁掉根侧，保留最常点击的最近父级。
- 每个祖先可点，点击等同于选中该任务：只切换详情内容，不切换视图。
- 多父时行尾显示 `+N`（N = 总链数 − 1），点开内联列表，每条路径一行，第一行固定是标题上方那条主链，其余按枚举顺序。
- 全部路径深度封顶 20、条数封顶 20；到上限时列表底部提示「仅显示前 20 条」。成环的分支只标记 `↻` 并停止回溯，不重复展开。
- 回收站里的已删除任务不在 `treeNodes` 中，父链整行不显示。

## 实现

- `frontend/src/utils/taskChain.js`：
  - `displayChainOf(treeNodes, id)` 建立首现实体节点索引后沿 `parent_id` 回溯，跳过 `_isRef` 回边节点、根任务与环；
  - `allChainsOf(items, id, { maxDepth, maxPaths })` 用任务数组建父级索引，深度优先枚举简单路径，返回 `{ chains, truncated }`，每条链带 `cycle` 标记。
- `components/TodoDetailEditor.vue`「[父链/面包屑]」放在详情分区内容顶部；角标展开的是内联面板，靠 `useSectionStack` 的 `auto` 高度自动重新测量，不浮在内容之上，避免被分区体 `overflow-hidden` 裁掉。
- 扁平任务由 `[rootTodo, ...tasks]` 拼回：store 的 `tasks` 已排除根任务，枚举时再补回。

## 取舍

- 不做「全部链路逐行常驻」：右栏宽 320px，多父或祖先分叉时行数会指数增长，把标题和描述整体往下推。
- 不做「只显示直接父级」：丢掉完整链路，无法判断当前任务挂在哪条分支下。
- 不做「祖先去重平铺」：节点数可控，但看不出哪几个祖先属于同一条链，和「链路」语义冲突。
- 路径枚举不缓存在 store：只在详情面板打开且主链非空时计算，封顶后成本有界。

## 验证

- `cd frontend && npx vitest run src/utils/taskChain.test.js`：覆盖单父回溯、顶层无链、回收站缺失、多父、祖先多父、环、条数截断。
- 手动：选一个多父任务，标题上方显示当前视图那条链；点 `+N` 展开全部路径，点任一祖先切到该任务详情；顶层任务不显示父链行；回收站任务不显示。
