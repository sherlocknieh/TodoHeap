# 任务图编辑时的缩放档位

双击节点或按 F2 进入编辑时，画布会先把缩放抬到「可读档位」，保证输入框里的字看得清；只在当前缩放更小时抬升，不会为了编辑而缩小。

## 实现

- `startEdit` 停掉正在跑的视图动画，再设 `editingId` / `editingText`，最后调 `ensureEditScale(node)`。
- 可读档位由 `readableScale()` 给出：`min(1, (visibleWidth - 96) / nodeWidth)`，下限 0.15。`visibleWidth` 扣掉右侧详情浮层，节点宽固定 216；宽视口封顶 `EDIT_SCALE = 1`（100%），可见区窄到放不下节点时按可用宽度缩小。
- `view.scale` 已经不低于档位时直接返回：手动放大到 150%、或刚从档位编辑过，都不改变缩放，也不触发动画。
- 需要抬升时把 `viewMode` 置空，再经 `animateView` 缓动到档位；x/y 由当前视口与节点中心反算，节点在屏幕上的位置保持不变，只以节点中心为锚点放大。
- 选中节点本身不再改变缩放（见[选中项的可见性修正](./mindmap-selection-visibility.md)），编辑档位与选中动作不会互相拉扯。

## 为什么封顶 100%

编辑要看清的是单个节点，原比例已经够用时不需要再放大；宽视口封顶 100% 避免突然撑大画面，窄视口仍退让到刚好放得下节点。选中只保证可见、不提供阅读档位，因此这个上限只服务编辑。

## 验证

1. 全景缩放到 80% 后双击节点：画布平滑放大到 100%，节点不跳位，编辑框立即可输入；
2. 选中任务后双击：缩放只受当前比例影响，与选中动作无关；
3. 当前 150% 时双击：缩放不变；
4. 详情右栏打开时双击：档位按扣除右栏后的宽度计算，放大后节点不会停在面板下面。
