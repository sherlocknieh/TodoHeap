# 任务多选

任务表的待办区与已完成区支持多选后批量删除。选择只影响界面，不写数据库；删除沿用软删除与撤销链路。

## 选择状态

- 选择保存为字符串任务 ID 集合，忽略数字/临时 ID 的差异；纯函数在 `utils/taskSelection.js`。
- 锚点只在 Shift 连选时使用：普通点击会清空选择，但把该行记为锚点，下一次 Shift 可直接从它开始连选；批量操作后锚点清空。
- 待办区收起、已完成按天收起后，离开 DOM 的行不参与连选。

## 操作条位置

- 选择集合全局一份，但操作按分区就地显示：已完成键由 `completed_at` 判定，其余算待办。
- 待办区有选择时，标题栏右侧把筛选、升降序与全部折叠换成「已选 N 项 + 删除 + 取消」；已完成区有选择时，同样替换该区的「清除已完成」。
- 两个分区可以同时保留选择，各自删除各自的键；分区收起时该区选择自动清空，避免隐藏的选中被误删。

## 点击链路

- 列表根节点用 **capture** 阶段监听点击，先于行自身的「打开详情」与拖拽点击处理。
- 行上用 `data-task-item` 标记、`data-task-id` 取任务 ID；`data-task-selectable="false"` 的回边行不可选。
- 分区用 `data-task-section` 区分待办与已完成；Shift 连选只在本分区内，按 DOM 可见顺序取两端之间的行。
- 点中行内按钮、输入框等交互元素时直接放行，避免抢占勾选、删除、截止时间等操作。
- 按住 Ctrl/⌘/Shift 时在 **mousedown** 阶段阻止默认行为，避免浏览器顺带选中行内文字；等到 click 阶段再阻止已经太晚。
- Ctrl/⌘ 切换单个任务；Shift 连选替换现有选择；没有修饰键的点击清空选择、记住锚点并照常打开详情，下一次 Shift 即可从该行连选。

## 批量删除

- 逐个调用 `todoStore.deleteTodo`：祖先先被删除后，其后代已不在任务列表，循环里自然跳过，避免重复入回收站。
- 撤销提示按首个删除结果里的回收站 ID 整批恢复；临时 ID 尚未落库，没有可恢复 ID 时不提供撤销。

## 回收站多选

- 回收站与任务表共用同一套选择纯函数：Ctrl/⌘ 切换、Shift 按可见行连选，普通点击清空并打开详情。
- 顶栏优先级：多选 > 单条选中 > 全局操作；多选时显示「已选 N 项 + 恢复 + 永久删除 + 取消」。
- 批量恢复按回收站树的从上到下顺序处理，父任务先恢复；父任务仍在回收站的任务改走 `restoreTodoToRoot`，断开回收站父链接并挂到根任务下。
- 批量永久删除沿用二次确认弹窗，父子同时选中时子任务只计一次；删除过程跳过已被祖先带走的任务。

## 验证

- `frontend/src/utils/taskSelection.test.js`：切换、正反向连选、锚点不可见退化、清理失效键。
- 手工验证：Ctrl 点两条待办、Shift 跨行连选、切到已完成区再 Shift 连选、批量删除后撤销。
