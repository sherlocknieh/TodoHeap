# 任务图选中项的可见性修正

选中任务只负责「让它处于可见区」，不自动居中、不定阅读档位；完整可见时视口完全不动。修正只针对来自图外的选中与键盘导航，图内点击本身就在可见区。

## 取舍

- 选中只回答「节点在不在可见区」，不承担「给节点一个阅读档位」；后者交给编辑档位与右下角目标按钮，避免同一个手势既选中又重排视野。
- 不做固定模板（父级、当前、子级各一栏）：模板与实际父子距离无关，叶子会预留空栏，还会在宽屏被档位上限压住。
- 只做最小平移、不做居中：居中会大范围移动视口，连续选中时画面反复跳，而居中并不是保持可见的必要条件。
- 可见区按扣除右侧浮层后的宽度计算，节点不会停在面板下面。
- 显式导航（任务行菜单「节点视图」）是例外：它要的是「把这条任务摆到眼前」，所以居中并固定 100%，不复用只保证可见的最小平移。

## 实现

- 视口变换是 `screen = view + world * scale`，可见区取 `visibleWidth`（画布宽扣掉详情右栏）与画布高。
- 图内点击：节点本来就在可见区，`selectNode` 只发选中事件，随后 `localSelection` 让 `selectedId` 监听跳过修正。
- 图外选中（任务列表、侧栏）与键盘导航：`selectedId` 变化后等布局稳定再调 `ensureNodeVisible`；被折叠隐藏时先展开祖先链。
- 从任务表「节点视图」进来时，选中态在导图挂载前就已存在，`selectedId` 监听不会触发；`focusTaskId`（来自路由 `?focus=`）在布局与画布尺寸就绪后调用 `centerNodeAtFullScale`：把节点摆到可见区中心、缩放固定 100%，缩放不因可见区变窄而缩小；被折叠隐藏时先展开祖先链。定位后清掉本地目标，避免后续重排再把视口拉回去。
- `ensureNodeVisible` 调 `utils/mindmapView.js` 的 `revealView`：节点矩形完整落在可见区内（留 24px 边距）时返回 `null`，不做任何动画；出界时只做最小平移，不改变缩放。
- 只有节点在当前缩放下比可见区还大时才缩小（不低于 0.15），缩到刚好放下并居中，避免只露出局部；从不为了选中而放大。
- 修正真的移动视口时把 `viewMode` 置空，右下角目标按钮回到「全景」入口；画布尺寸变化不再自动跟随选中项。

## 验证

1. 节点完整可见时单击：选中、详情更新，画面不动；
2. 从任务列表选中视口外的任务：只平移最小距离把它带回，缩放不变；被折叠时先展开祖先；
3. 键盘方向键连续导航：选中项始终留在可见区，比例不变；
4. 放大到 250% 后从列表选中一个装不下的任务：缩到刚好放下并居中；
5. 右侧详情面板打开时，修正按扣除面板后的宽度计算，节点不会停在面板下面；
6. 从任务表行内菜单「节点视图」：切到任务图，目标节点居中且缩放为 100%，目标被折叠时先展开祖先链；之后在图中平移、增删任务不会再被拉回该节点。
