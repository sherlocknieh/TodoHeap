# 侧栏开合与窗口宽度

左侧栏有两种形态：宽屏（≥ 768px）下是挤压中栏的常驻栏，窄屏下是覆盖内容的浮层抽屉。显示状态因此拆成两套，互不覆盖。

## 状态构成

| 状态 | 持久化 | 作用范围 |
| --- | --- | --- |
| `sidebar-open`（宽屏偏好） | 是，`todoheap:ui:sidebar-open` | 只是宽屏下是否显示侧栏，由用户手动开合决定 |
| 抽屉开关（窄屏） | 否，仅当次会话 | 窄屏浮层是否展开，收窄时自动关闭 |

`showLeftSidebar` 是 computed，按当前宽度选择上面哪套：

- 宽屏读写 `sidebar-open`；
- 窄屏读写抽屉开关。

因此同一处「关闭侧栏」在两种宽度下影响不同状态，不会把窄屏的一次收起写成宽屏偏好。

## 宽度变化的规则

`window.addEventListener('resize')` 只做两件事：更新 `windowWidth`（供浮层判定），以及在**从宽屏收窄到窄屏**时把抽屉关掉，避免浮层盖住清单。

放手规则是「宽度只决定用哪套状态」：

- 宽屏拖窗口不会展开或收起侧栏，用户的偏好保持不变；
- 窄屏拉宽后显示宽屏偏好，偏好为收起就继续收起；
- 切换活动栏入口（清单／日程／AI）时宽屏打开侧栏展示该入口内容，窄屏保持抽屉关闭。

断点常量 `SIDEBAR_FLOAT_BREAKPOINT = 768` 需与模板里的 `md:` 保持一致。

## 验证

1. 宽屏收起侧栏，反复拖动窗口宽度（含跨越 768px），侧栏保持收起；
2. 宽屏展开侧栏，收窄到 768px 以下，浮层自动关闭且不遮住中栏；再拉宽，侧栏按偏好恢复展开；
3. 窄屏点 AI 侧栏里的会话、通知等入口时抽屉打开，点击浮层外关闭；
4. 刷新页面后，宽屏偏好与刷新前一致。

## 侧栏分区栈（任务 / 日程 / AI）

三个活动栏入口的侧栏都使用同一套可折叠分区栈，布局参考 VSCode 的视图栈：

| 入口 | 分区（按顺序） |
| --- | --- |
| 任务 | 视图 |
| 日程 | 概览、说明 |
| AI | 对话、MCP 服务、技能 |

- 分区顺序固定，折叠状态记在 `collapsedSections`（`sidebar-sections`），本地保留；
- 全部折叠时标题行贴顶排列，下方留白；
- 只有一个分区展开时，它取 `flex-1` 占满剩余高度；
- 多个分区展开时，按顺序第一个展开的分区占满剩余高度，其余展开分区统一 192px（`SECONDARY_SECTION_HEIGHT`）；
- 技能区作为非首位展开分区时沿用可拖拽高度（`skillsHeight`），排首位展开（已占满高度）时隐藏上缘拖拽条；
- 分区高度以像素写入，展开/折叠时做 200ms `height` 过渡；内容始终保持挂载，折叠时用 `inert` 阻止交互，靠分区 `overflow-hidden` 裁剪；
- 拖动技能区分隔条期间关闭过渡，高度跟手变化。

分区顺序与分组键见 `SIDEBAR_SECTIONS`，尺寸由 `sectionClass`、`sectionStyle`、`measureSectionHeights` 统一计算。每个分区的内容区都是 `flex-1 min-h-0 overflow-auto`：分区高度确定后只有内容列表滚动，标题行保持可见。

### 验证

1. 三个入口分别折叠全部分区，标题贴顶且下方留白；
2. 只展开一个分区，它占满整栏；
3. 同时展开多个分区，首个展开的分区占满，其余为统一高度并各自滚动；
4. 技能区非首位展开时可用分隔条调高；技能区排首位展开时没有分隔条；
5. 点击分区标题展开或折叠，高度有约 200ms 的平滑过渡，相邻分区同步让位；拖动技能区分隔条时高度即时跟手，没有过渡延迟。
