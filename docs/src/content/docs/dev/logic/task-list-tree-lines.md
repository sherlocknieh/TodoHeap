# 任务表树状连线

本页说明任务表（列表视图）里层级连线与折叠开关的位置怎么算、怎么画。它只负责「看清层级」：不表达拖拽落点，也不改变任务的父子关系。功能行为见[视图与交互](../../features/views.md)。

## 渲染行与可见性

- 连线只画在真正渲染出来的行上，因此先由 `visibleRows`（`components/TodoListItem.vue`）把 `flatList` 过滤成可见行，再给每行补两个展示字段：`_guides`（各祖先层是否继续画竖线）与 `_lastSibling`（自己是不是最末一个可见兄弟）。
- 可见性仍复用 `isItemVisible`：完成态优先看 `statusMap`（行内点击后先变，再落库），折叠态读 `utils/taskCollapse.js`。行顺序与 `_level` 都来自 `flattenTree`，不另建树。
- 为什么不在模板里判断兄弟：可见行由「完成态 + 折叠态」共同决定，并且会随乐观更新即时变化；把它们收进一个 computed，模板只负责按算好的布尔值挂线，行增删时连线自动跟着重排。

## 兄弟与末位

- 同一个父级、同一层级的最后一个可见行就是末位，用 `parent_id@_level` 作为分组键记录（`lastVisible`）。`_lastSibling` 为真时自己的竖线只画到行中心，收成 `└` 角；否则竖线贯穿整行，形成 `├`。
- 只有可见行参与末位判定：隐藏一个已完成或折叠的兄弟后，前一个兄弟会自动变成末位，连线不会留空。
- 祖先层是否继续画竖线，取决于该祖先自己是否还有后续可见兄弟（`hasNextSibling`）；祖先本身被隐藏时，它那一层不画线，避免出现无主竖线。

## 几何

- 缩进、连线与卡片内圆钮共用一套尺寸：横线 `ELBOW_WIDTH = 10`，卡片左缘到圆钮圆心 `CHECKBOX_CENTER_INSET = 18`（边框 1 + 左内距 8 + 半径 9），所以每层 `LEVEL_INDENT = 28`。竖线 `guideLeft(level) = level * LEVEL_INDENT + GUIDE_OFFSET`（`GUIDE_OFFSET = 12`），卡片 `rowPaddingLeft(level) = guideLeft(level) + ELBOW_WIDTH`。这样第 `level` 层的竖线正好是第 `level - 1` 层圆钮（勾选圈或折叠开关）的圆心，连线看起来从父任务圆钮下方垂下来；横线正好从竖线顶到卡片左缘，不需要读卡片的实际宽度。改缩进或卡片左内距时必须同步这三个常量，否则竖线会重新偏离圆钮圆心。
- 卡片最左侧的圆钮按子任务状态切换：有未完成子任务时渲染折叠开关（`hasActiveChildren` / `isTaskDone`），子任务全部完成或本来就是叶子时渲染勾选圈；两者同尺寸、同位置，缩进与连线不受影响。
- 折叠开关不再绝对定位：它与勾选圈共用卡片内的 18px 圆形槽位（`h-[18px] w-[18px]`，左内距 8 + 半径 9），圆心距卡片左缘 18px。开关渲染在卡片内，天然落在子级竖线的延长线上，不再需要 `bg-canvas` 遮盖穿过圆心的连线，也不会露到卡片外面。
- 顶层（`_level === 0`）没有连线，但缩进位仍从 `GUIDE_OFFSET` 起算：卡片左缘 22px，卡片内圆钮圆心 22 + 18 = 40px，正好等于下一层竖线的 x。快速添加栏的 `ml-[22px]`、已完成列表的 `pl-[22px]` 都与之对齐：已完成行保留同一左内距，两类卡片左缘才落在同一条竖线上。
- 行高由行内按钮决定，稳定在 42px；列表间距是 6px，竖线用 `-top-1.5` / `-bottom-1.5`（即上下各探出 6px）跨过间距接上相邻行，横线在行中心接入卡片左缘。
- 末位的竖线用 `height: calc(50% + 6px)` 从间距顶端连到行中心；非末位用 `top/bottom: -6px` 贯穿整行。连线都是 `pointer-events-none` 的 1px 绝对定位块（`itemGuideStyle`、`elbowStyle`），不占布局，也不会挡住行点击、悬停与拖拽。
- 颜色沿用 `hairline` 令牌（`bg-hairline/70 dark:bg-hairline-dark/70`），与卡片描边同族，深浅主题都不需要单独开关。

## 约束与边界

- 第一层（`_level === 0`）不画连线：列表把根任务的子级作为顶层展示（`utils/rootTask.js` 的 `listTreeOf`），顶层卡片之间没有共同的父级轴线；卡片内的开关或勾选圈仍按同一套 18px 槽位对齐。
- 每个顶层节点由独立的 `TodoListItem` 渲染，连线只在同一棵子树内连续；跨顶层节点不会串线。
- 引用行（`_isRef`）与真实行参与同一套缩进、连线与卡片外观，不靠颜色或虚线弱化；它们的 `_level` 取决于被渲染的位置，而不是被引用任务原本的层级。区别只在能力上：引用行没有自己的子级，左槽恒为勾选圈；不可拖拽、不可多选，也不作为拖拽落点。
- 已完成任务不进待办行，但其子任务仍按原有可见性规则显示，此时该行只保留自身层与横线，不补已完成父级那一层的竖线。

## 验证

- 手动：在 `/TodoHeap/app/#/list` 检查多层嵌套、末位收角、折叠/展开父级、勾选完成后连线是否重排；引用行与实体行外观一致（勾选圈、文字颜色、实线边框、行内操作都相同），同样有横线接入，但引用行左槽恒为勾选圈、不可拖拽。有未完成子任务的行，卡片最左侧应是圆形 +/−，叶子任务是圆形勾选圈，二者圆心都距卡片左缘 18px；子行竖线的 x 应等于上一级圆钮圆心 x（父行卡片左缘 + 18），横线末端应正好落在子行卡片左缘。
- 自动：`cd frontend && npx vitest run`。连线是展示层，现有用例只覆盖可见性与排序相关工具；改动几何或分组键时至少回归一次列表页。
