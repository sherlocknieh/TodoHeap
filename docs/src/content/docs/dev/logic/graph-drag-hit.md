# 任务图拖拽命中与空隙预览

本页说明拖节点时如何判定落点：拖到节点上（成为子级）、拖到节点边缘或子级之间（插入槽位）分别怎么算、怎么预览。移动/链接写入规则见[视图与交互](../../features/views.md)，坐标与分层见[任务图布局逻辑](./mindmap-layout.md)。

---

## 一、判定总纲（影子中心落在哪）

被拖实节点的中心（`dragState.shadow` 的中心）对标某个节点时，水平位置直接决定落点类型：

| 影子中心水平位置 | 落点 | 说明 |
| --- | --- | --- |
| 节点**出边侧** 1/3 带（含该侧外侧；右展开是右侧，左展开是左侧） | **拖入命中** | 成为该节点的子级 |
| 其余位置（中间 1/3 与入边侧 1/3） | **兄弟命中** | 插到该节点前/后（按中心在它上半/下半），归它所在父级的兄弟槽位；多父任务取视图里最近的父级 |

入边侧那 1/3 留给兄弟命中：它朝向父级，如果也按拖入处理，会和父级方向的落点互相抢。两类只要求影子与节点在**竖直方向有交集**（用来确定对准的是上下哪个节点），不看面积或交并比，拖入命中不设竖直重叠比例阈值；还要与节点横向有交集。中心在节点宽度之外、且影子已与节点无交集时，交给子级列空隙与叶子出边区判定。

## 二、命中顺序

拖节点的落点以**被拖实节点的中心**为参照方向，命中目标则由影子与节点的**竖直重叠度**决定，不看面积或交并比。

1. **中心还在源节点原位**：拖动尚未离开，不判定落点、不出预览。
2. **节点命中**：`findVerticalDropTarget`（`utils/mindmapDrag.js`）取影子与节点竖向重叠最大者，再按上面的总纲分派：
   - 中心在中间 1/3 或入边侧 1/3 → 兄弟命中：插到它前/后，方向按中心在它上半还是下半，归它父级的兄弟槽位（`childEdgeBand`）。
     多父任务在视图里可能同时靠向多条父链：`nearestVisibleParentId` 在它所有父级中取视图位置离落点最近的一个，兄弟顺序与锚点都按那条父链算（引用节点按被引用任务 id 参与顺序）。
   - 中心在出边侧 1/3 带 → 拖入命中：成为它的子级，不设竖直重叠比例阈值；拖到**自己的任一父节点**上（多父任务也包括其它父链）等同于原地不动，静默无操作、不提醒；拖到**根节点**上不接受落点。
3. **中心在叶子节点的出边区**：`findLeafEdgeTarget` 命中该叶子，成为它的子级（影子与它横向错开、竖直重叠命中不到时仍有落点）。
4. **中心在父级子级列的空隙**：`findChildGapTarget` 把父级可见子级列里的空白判给父级。
   - 候选按布局节点的 `parent_id`（树展开时的显示父级）分组；引用节点与占位节点不参与。
   - 子级列纵向范围是首子级上缘到末子级下缘；首/末外侧再放宽 `24 / scale`（上限 48 图内单位），方便插到首位/末位。
   - 横向要求中心落在子级列范围内（含边界）。
   - 槽位序号 = 中心纵向位置越过了几个子级中心；首子级上缘处为 0，末子级下缘处为子级数。
   - 按锚点插回原位置（含插到自己前后）视为无落点：`keepsOriginalOrder` 比较插入前后的兄弟顺序，相同就不预览、松手也不提交。
   - 多个父级的子级列纵向重叠时取子级列中心更近的一个；被拖节点自己作为父级的子级列不参与。
   - 折叠父级没有可见子级，不产生空隙落点。
5. **其它位置**：没有落点，不显示任何预览。

按钮拉线（从折叠/加号按钮拖出）仍用 `linkTargetAtRect`：以指针点到节点矩形的距离判定，按屏幕像素外扩 24（上限 48 图内单位）。

## 三、命中后的反馈

- 落点父级按「拖进节点」高亮（`isDropInside`）：拖到节点上时高亮该节点，槽位落点高亮它的父级。
- 三种命中都显示同一套预览：拖到节点上（成为它的子级）、拖到节点边缘（插到它前/后）、拖到子级列空隙（插到对应序号）。
- `insertDropPlaceholder` 在父级子级列表的锚点位置插入虚节点：高度等于被拖节点（`dragState.sourceHeight`），布局按它真实让位。拖进节点与叶子出边区命中时锚点为空，虚节点插到该父级子级列表末尾（叶子没有子级，就是第一个），正好落在出边方向。
- 虚节点渲染两层：浅底画在实节点影子下层；虚线轮廓画在影子之上，与被拖节点重合时仍能看清插入位置的边框。
- 被拖的实节点卡片始终跟着指针（`dragState.shadow`），不会被虚节点替换，拖动时始终看得到节点本身。
- 兄弟节点让出的空位由布局真实重排；被拖节点本身仍在原始位置淡出，与虚节点各占一处。
- `dropPreviewLink` 用 `createEdge` 生成从父级到虚节点的曲线，以虚线强调色画在最上层（节点与影子之上），表示插入后的链接。
- 虚节点只参与渲染用的 `layout`；命中仍用不含虚节点的 `hitLayout`，避免目标被顶走后反复抖动。
- 落点父级若是折叠状态，**保持折叠**：布局只放出占位节点、不展开原有子树，表现与落到叶子节点上一致；折叠计数不因占位节点变化。

## 四、提交的落点

- 松手时 `onDragEnd` 发出 `drop-task`：`parentId = 父级`、`position = 'inside'`、`insertBeforeId` / `insertAfterId` 为锚点直接子级。
- 叶子出边区命中没有锚点，直接按「成为该父级子任务」提交，走 `dropTask` 的拖进分支（单父移动、多父加链接）。
- 插入后兄弟顺序与拖动前一致（`keepsOriginalOrder`）时不提交，避免拖动没换位置也写一次 `child_ids`。
- `TodoGraph.vue` 的 `insertIntoParent` 分派：
  - 已是该父级子任务 → `moveTodo` 按锚点重排。
  - 多父任务 → 只在该父级 `child_ids` 的锚点位置加一条链接，提示可「改为移动（断开旧连接）」。
  - 单父任务 → `moveTodo` 移动到锚点位置；换父级时摘掉来源父链接。
- 顺序的最终依据仍是 `child_ids`，插入规则见[任务顺序](./task-order.md)。

## 五、验证

1. 展开一个有多个子节点的父级，把另一个节点拖到两个子节点之间的空白里（影子与两侧子节点重叠都不足一半）：父级高亮，空隙出现与被拖节点同尺寸的虚线虚节点，父级到虚节点有虚线。
2. 拖到子节点本体、影子与它大半重叠：命中该子节点本身（可以成为它的子级）。
3. 拖到子级列范围之外（首子级上方、末子级下方更远处）：不命中。
4. 从节点自己身上开始拖动（中心还没离开它）：不出现任何落点预览，父级也不高亮。
8. 拖到自己的父级里但插回原位（前任或后一兄弟的槽位与自己原位等价）：不预览、松手不写入。
9. 拖到根节点本体或它的出边区：不出现任何预览，松手不改变任何结构。
10. 把一个任务拖到叶子节点的右缘外一小段（`left` 布局为左缘外）：同样命中该叶子。
11. 折叠父级参与空隙判定时不产生空隙落点（没有可见子级）。
