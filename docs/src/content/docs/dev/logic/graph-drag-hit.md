# 任务图拖拽命中与空隙预览

本页说明拖节点时如何判定落点，以及「拖到父节点子级之间的空隙」如何命中父节点、如何预览。移动/链接写入规则见[视图与交互](../../features/views.md)，坐标与分层见[任务图布局逻辑](./mindmap-layout.md)。

---

## 一、命中顺序

1. **指针在节点内**：`nodeAtPoint` 命中该节点，落点仍按指针在节点内的纵向位置分派（上/下四分之一前后插序、中间拖进）。
2. **指针在父级子级列的空隙**：`findChildGapTarget`（`utils/mindmapDrag.js`）把父级可见子级列里的空白判给父级。
   - 候选按布局节点的 `parent_id`（树展开时的显示父级）分组；引用节点与占位节点不参与。
   - 子级列纵向范围 = 首子级上缘到末子级下缘；首/末外侧再放宽 `24 / scale` 屏幕像素（上限 48 图内单位）。
   - 纵向用**指针位置**判定，横向用影子宽度与子级列是否重叠。影子几乎总会压到相邻子节点，若按影子矩形接触判定，子节点的前后插序会抢先，空隙永远命中不了。
   - 槽位序号 = 指针纵向位置越过了几个子级中心；首端之前为 0，末端之后为子级数。
   - 指针仍在源节点原矩形内时（拖动尚未离开）不做任何落点判定，不出现预览。
   - 按锚点插回原位置（含插到自己前后）视为无落点：`keepsOriginalOrder` 比较插入前后的兄弟顺序，相同就不预览、松手也不提交。
   - 相邻父级的接近范围重叠时取子级列中心更近的一个；被拖节点自己作为父级的子级列不参与。
   - 折叠父级没有可见子级，不产生空隙落点。
3. **影子与节点接触**：指针不在任何节点内、也不在任何子级列空隙时，`linkTargetAtRect` 按影子矩形与节点是否接触判定，多个候选取中心最近者。保留「不用把指针放到节点上也能命中」。

## 二、命中后的反馈

- 父级按「拖进节点」高亮（`isDropInside`）。
- `insertDropPlaceholder` 在父级子级列表的锚点位置插入虚节点：高度等于被拖节点（`dragState.sourceHeight`），布局按它真实让位；虚节点用虚线框渲染，并沿用被拖节点的文字排版，尺寸与原件一致。
- 空隙命中时隐藏指针处的影子副本（`dragState.childBand` 为真时影子透明），视线交给槽位里的虚节点。
- `dropPreviewLink` 用 `createEdge` 生成从父级到虚节点的曲线，以虚线强调色画在最上层（节点与影子之上），表示插入后的链接。
- 占位槽只参与渲染用的 `layout`；命中仍用不含占位槽的 `hitLayout`，避免目标被顶走后反复抖动。

## 三、提交的落点

- 松手时 `onDragEnd` 发出 `drop-task`：`parentId = 父级`、`position = 'inside'`、`insertBeforeId` / `insertAfterId` 为锚点直接子级。
- 插入后兄弟顺序与拖动前一致（`keepsOriginalOrder`）时不提交，避免拖动没换位置也写一次 `child_ids`。
- `TodoGraph.vue` 的 `insertIntoParent` 分派：
  - 已是该父级子任务 → `moveTodo` 按锚点重排。
  - 多父任务 → 只在该父级 `child_ids` 的锚点位置加一条链接，提示可「改为移动（断开旧连接）」。
  - 单父任务 → `moveTodo` 移动到锚点位置；换父级时摘掉来源父链接。
- 顺序的最终依据仍是 `child_ids`，插入规则见[任务顺序](./task-order.md)。

## 四、验证

1. 展开一个有多个子节点的父级，把另一个节点拖到两个子节点之间的空白里（指针在空隙中）：父级高亮，空隙出现与被拖节点同尺寸、同文字的虚线虚节点，父级到虚节点有虚线。
2. 拖到父节点本体：命中父节点，仍按上/下四分之一前后插序、中间拖进，不走空隙规则。
3. 拖到首子级上方或末子级下方：接近范围内命中父级并插到首/末位，远离则不命中。
4. 从节点自己身上开始拖动（指针还没离开它）：不出现任何落点预览，父级也不高亮。
5. 拖到自己的父级里但插回原位（前任或后一兄弟的槽位与自己原位等价）：不预览、松手不写入。
6. 拖到子节点本体：命中该子节点，显示原来的排序占位槽（左缘细条）。
7. 折叠父级：不产生空隙落点。
