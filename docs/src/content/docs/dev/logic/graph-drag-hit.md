# 任务图拖拽命中与空隙预览

本页说明拖节点时如何判定落点，以及「拖到父节点子级之间」或「拖到子节点本体」时如何命中父节点、如何预览。移动/链接写入规则见[视图与交互](../../features/views.md)，坐标与分层见[任务图布局逻辑](./mindmap-layout.md)。

---

## 一、命中顺序

拖节点的落点**只由指针位置决定**，不看影子矩形与节点的接触。

1. **指针在源节点原位**：拖动尚未离开，不判定落点、不出预览。
2. **指针在节点内**：`nodeAtPoint` 命中该节点，节点内**没有**「拖进」区域。
   - 上半插到该节点之前、下半插到之后；落点归该节点**所在父级**的兄弟槽位（`childEdgeBand`），与空隙命中共用同一套虚节点 + 虚线预览，不再单独画 20px 的前后插序小槽。
   - 根节点（以及无父级的孤立节点）没有兄弟序列：指针在它身上按「回到顶层」处理，即拖进根任务。
   - 因此把任务挂到某个节点下，靠的是拖到该节点父级的子级列（或它的子级列），而不是压在节点本身。
3. **指针在叶子节点的出边区**：`findLeafEdgeTarget` 命中该叶子，落点语义是「成为它的子级」。
   - 只对没有可见子级的节点生效（有子级的节点这一侧是它的子级列，另有规则）。
   - 横向只看出边方向的一小段：`right` 方向是节点右缘到右缘外 `24 / scale`（上限 48 图内单位），`left` 方向对称；纵向严格在节点高度内。
   - 叶子没有子级列，没有这块区域就无法把任务挂到它下面。
4. **指针在父级子级列的空隙**：`findChildGapTarget`（`utils/mindmapDrag.js`）把父级可见子级列里的空白判给父级。
   - 候选按布局节点的 `parent_id`（树展开时的显示父级）分组；引用节点与占位节点不参与。
   - 子级列纵向范围严格等于首子级上缘到末子级下缘，列外不命中。
   - 横向要求指针落在子级列范围内（含边界）；指针宽度为零，不做外扩。
   - 槽位序号 = 指针纵向位置越过了几个子级中心；首子级上缘处为 0，末子级下缘处为子级数。
   - 按锚点插回原位置（含插到自己前后）视为无落点：`keepsOriginalOrder` 比较插入前后的兄弟顺序，相同就不预览、松手也不提交。
   - 多个父级的子级列纵向重叠时取子级列中心更近的一个；被拖节点自己作为父级的子级列不参与。
   - 折叠父级没有可见子级，不产生空隙落点。
5. **其它位置**：没有落点，不显示任何预览。

按钮拉线（从折叠/加号按钮拖出）仍用 `linkTargetAtRect`：以指针点到节点矩形的距离判定，按屏幕像素外扩 24（上限 48 图内单位）。

## 二、命中后的反馈

- 落点父级按「拖进节点」高亮（`isDropInside`）：空隙与节点上半/下半都指向父级。
- `insertDropPlaceholder` 在父级子级列表的锚点位置插入虚节点：高度等于被拖节点（`dragState.sourceHeight`），布局按它真实让位。叶子出边区命中时锚点为空，虚节点直接成为该叶子的第一个子级，正好落在它的出边方向。
- 虚节点渲染两层：浅底画在实节点影子下层；虚线轮廓画在影子之上，与被拖节点重合时仍能看清插入位置的边框。
- 被拖的实节点卡片始终跟着指针（`dragState.shadow`），不会被虚节点替换，拖动时始终看得到节点本身。
- 兄弟节点让出的空位由布局真实重排；被拖节点本身仍在原始位置淡出，与虚节点各占一处。
- `dropPreviewLink` 用 `createEdge` 生成从父级到虚节点的曲线，以虚线强调色画在最上层（节点与影子之上），表示插入后的链接。
- 虚节点只参与渲染用的 `layout`；命中仍用不含虚节点的 `hitLayout`，避免目标被顶走后反复抖动。

## 三、提交的落点

- 松手时 `onDragEnd` 发出 `drop-task`：`parentId = 父级`、`position = 'inside'`、`insertBeforeId` / `insertAfterId` 为锚点直接子级。
- 叶子出边区命中没有锚点，直接按「成为该父级子任务」提交，走 `dropTask` 的拖进分支（单父移动、多父加链接）。
- 插入后兄弟顺序与拖动前一致（`keepsOriginalOrder`）时不提交，避免拖动没换位置也写一次 `child_ids`。
- `TodoGraph.vue` 的 `insertIntoParent` 分派：
  - 已是该父级子任务 → `moveTodo` 按锚点重排。
  - 多父任务 → 只在该父级 `child_ids` 的锚点位置加一条链接，提示可「改为移动（断开旧连接）」。
  - 单父任务 → `moveTodo` 移动到锚点位置；换父级时摘掉来源父链接。
- 顺序的最终依据仍是 `child_ids`，插入规则见[任务顺序](./task-order.md)。

## 四、验证

1. 展开一个有多个子节点的父级，把另一个节点拖到两个子节点之间的空白里（指针在空隙中）：父级高亮，空隙出现与被拖节点同尺寸的虚线虚节点，父级到虚节点有虚线。
2. 拖到子节点本体上半/下半：命中它的父级，槽位在该子节点前/后，节点内没有「拖进」。
3. 拖到子级列范围之外（首子级上方、末子级下方更远处）：不命中。
4. 从节点自己身上开始拖动（指针还没离开它）：不出现任何落点预览，父级也不高亮。
5. 拖到自己的父级里但插回原位（前任或后一兄弟的槽位与自己原位等价）：不预览、松手不写入。
6. 拖到根节点本体：按回到顶层处理。
7. 把一个任务拖到无子级节点的右缘外一小段（`left` 布局为左缘外）：该节点高亮，出边方向出现虚节点与虚线，松手后成为它的子级。
8. 折叠父级：不产生空隙落点。
