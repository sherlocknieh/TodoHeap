# 任务图粘贴为子任务

任务图选中节点后按 Ctrl/⌘+V，把剪贴板文本建成该节点的子任务：Markdown 列表还原成多层子树，其它纯文本建成单个子节点。

## 触发与读取

- 粘贴挂载在导图容器上（`MindMapWrapper.vue` 的容器 `tabindex="0"`，点击画布会把焦点还给容器），`onPaste` 读 `clipboardData` 的纯文本，不需要浏览器剪贴板权限。
- 部分浏览器不在非编辑区派发 `paste` 事件：`onKeydown` 的 Ctrl/⌘+V 分支在下一轮事件循环检查是否已处理，没处理才用 `navigator.clipboard.readText()` 兜底；读取被拒时轻提示「无法读取剪贴板，请允许读取权限后重试」。
- 编辑中（节点文字输入框、日期面板等可编辑元素）不拦截粘贴，交给浏览器正常粘贴文字。
- 没有选中节点、或剪贴板没有可用文本时不动作。

## 粘贴目标

- 多选时取选择集合里的第一个节点作为父级，其余选中节点不变。
- 单选根节点时新任务落到顶层；合成根（根任务还没拉到的占位）没有真实父级，等同顶层。
- 不进入编辑态：标题已由剪贴板给定，粘贴后只选中第一个新任务。

## 文本解析（`utils/taskPaste.js`）

- 首个非空行是列表项才按列表解析，否则整段文本压成一行作为单个标题。
- 列表项接受 `-`、`*`、`+` 与 `1.` / `1)` 序号；缩进用前面的空白衡量，制表符按两个空格折算（与复制时的缩进单位一致），缩进栈按「变浅就回退同级、变深就挂上一项下面」还原层级。
- 空标题的项被剔除，它的子级上提到上一层，避免粘贴出空任务。

## 落库与顺序

- `TodoGraph.vue` 的 `createTask` 收到 `paste` 树后交给 `pasteTasks`：逐层调用 `addTodo`，子级先建父级再建子级。
- `addTodo` 把新任务头插进父级 `child_ids`，所以**同级倒着建**，建完 `child_ids` 就是剪贴板顺序。
- 顶层组建完后用一次 `updateTodo(父级, { child_ids })` 把它接到原有子级之后，与图上新建追加到末尾的约定一致（见[任务顺序](./task-order.md)）；子级没有原有兄弟，不需要额外重排。
- 父级 `child_ids` 里此时还是临时 ID，这条 `UPDATE` 由同步队列等对应 `ADD` 落地后再发，机制见[任务创建逻辑](./task-create.md)「父级 child_ids 更新的顺序约束」。

## 验证

- 单测：`frontend/src/utils/taskPaste.test.js`（缩进还原、序号/星号/制表符、纯文本压行、空标题上提、空文本）。
- 命令：`cd frontend && npm test`、`nub run build`。
- 手工：`Ctrl+C` 复制一棵子树后选中另一节点 `Ctrl+V`，核对层级与顺序；粘贴纯文本与多选后的粘贴。
